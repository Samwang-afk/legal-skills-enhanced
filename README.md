## 关于项目

**Legal Skills w/Ludus Agent** 是一套开源的中文法律工作 Skill 集合。

它不是一个“万能律师提示词”，也不试图让单个模型直接完成从事实判断到正式文书交付的全部工作，而是把真实法律服务中容易被模型忽略的流程、校验、分工和交付边界拆解为可由 AI Agent 执行和复核的工作单元。

原有 **Legal Skills** 负责法律业务执行：

* 法律咨询；
* 民事诉讼；
* 刑事辩护；
* 劳动争议；
* 破产程序；
* 合同与交易；
* 产品法务；
* 监管合规；
* 法规案例检索；
* 证据分析；
* 法律文书；
* 正式交付。

**Ludus Agent** 不替代这些专业 Skill，而是增强法律工作总控在复杂任务中的问题澄清和反向审查能力。

简单来说：

> **先问对问题，再做法律工作；先检查结论能不能被推翻，再把它写进正式文书。**

Agent 在本项目中不会被鼓励直接从用户输入跳到正式法律结论，而是按法律工作习惯推进：

* 先识别任务类型，再选择对应专业 Skill；
* 先读取已有材料，再决定是否需要向用户追问；
* 不因为“信息缺失”就机械提问，只追问真正可能改变法律判断的关键缺口；
* 区分已确认事实、用户或当事人主张、争议事实和模型推断；
* 对复杂或存在争议的事项，从支持与反对两个方向复核核心判断；
* 涉及法规、案例、政策或规范性文件时，披露来源和校验状态；
* 材料不足、OCR 存疑、事实冲突、期限风险和授权不明时，明确提示；
* 生成正式 Word 文书前，继续经过原有出稿前审查和导出质量门；
* 对外输出始终保留律师、法务或其他专业人士的人工复核空间。

> **重要提示：本项目不提供法律意见。**
>
> 本项目输出的任何内容都应视为供律师、法务或合格专业人士复核的工作草稿。真实法律事项必须由专业人士基于完整事实、有效授权、现行法律、可核验案例和具体语境作出独立判断。

## 项目概述

法律工作并不只是“给模型一个问题，让模型回答”。

真实业务通常同时受到事实、证据、法律关系、程序、期限、授权、检索、格式和交付对象等多重约束。

Legal Skills 主要解决：

1. **任务路由不稳定**：同一句“帮我看看这个案子”，可能实际需要咨询回复、诉讼分析、证据审查、法规检索、文书起草或案件管理。
2. **材料读取不透明**：法律结论依赖文件内容，需要文件读取、OCR、关键信息提取、完整性复查和存疑项披露。
3. **法规案例容易失真**：模型可能凭记忆引用失效、错误或不存在的法条和案例，因此需要来源校验。
4. **法律文书容易跳步骤**：起诉状、答辩状、代理词、合同和法律报告不能只追求“写得像”，还需要事实、结构、来源和 DOCX 交付检查。
5. **模型容易过早下结论**：用户对事实和法律关系的描述未必就是最终法律定性，复杂事项需要保留不同解释并主动检查反例。
6. **本地业务系统难以迁移**：律师和团队通常拥有自己的客户台账、文件夹、云文档、OCR、案例库和知识库，需要明确配置边界。

### 核心特点

* **法律工作总控**：统一路由、事项隔离、材料读取复查、法规案例校验、来源边界和质量门调度。
* **Ludus 推理增强**：复杂或信息不足的任务先识别真正影响判断的关键缺口，必要时最小追问，并从支持与反对两个方向复核核心结论。
* **专业业务 Skill**：覆盖民事诉讼、刑事辩护、劳动争议、破产程序、合同、产品法务、监管合规、法律咨询和法律研究。
* **正式交付质量门**：正式 Word、正式报告、业务流程图、修订稿等均设置明确终检规则。
* **真实 DOCX 红线能力**：合同审查支持生成带真实修订痕迹和批注的 Word 审核修订稿。
* **模板克隆导出能力**：要素式起诉状可使用 DOCX 母版克隆填充，保留复杂表格、合并单元格和版式结构。
* **本地化友好**：业务配置中的身份信息、本机路径、客户台账和外部凭证可以通过配置边界替换。

## 架构

Ludus Agent 不作为一套平行的法律系统存在，而是增强原有法律工作总控。

```text
用户任务
  │
  ▼
法律工作总控
  - 语义路由
  - 事项隔离
  - 材料读取复查
  - 关键缺口识别与必要追问
  - 复杂事项正反复核
  - 法规/案例校验
  - 来源边界
  - 输出底线
  │
  ▼
专业业务 Skill
  - 民事诉讼
  - 刑事辩护
  - 劳动争议
  - 破产程序
  - 合同与交易
  - 产品法务与合规
  - 法律咨询与检索
  │
  ▼
交付质量门
  - 出稿前审查
  - 文书模板与导出
  - DOCX 结构检查
  - 缺口与风险提示
```

也就是说：

> **Ludus 负责帮助 Agent 想得更稳，Legal Skills 负责把法律工作做出来，原有质量门负责检查最终交付。**

对于简单、明确的问题，不会强制启动复杂的正反分析流程。

例如：

```text
劳动合同试用期最长多久？
```

仍然应在完成必要法律来源核验后直接回答。

只有涉及事实冲突、多种法律关系、重要策略选择或正式高风险交付时，才需要更强的澄清和反向检查。

## 典型工作流

#### 案件材料分析

```text
用户上传案件材料
  │
  ▼
法律工作总控识别事项
  │
  ▼
逐一读取 PDF、Word、图片、表格或网页
  │
  ▼
提取主体、金额、日期、证据和争议焦点
  │
  ▼
识别真正影响判断的缺口
  │
  ├─ 可以从材料确定 → 直接读取
  ├─ 不影响核心判断 → 记录后继续
  └─ 会改变核心判断 → 向用户聚焦追问
  │
  ▼
初步法律分析 / 证据分析 / 法规案例检索
  │
  ▼
复杂事项进行正反复核
  │
  ▼
进入诉讼方案、文书起草或其他专业 Skill
```

#### 合同审查

```text
合同文本或文件
  │
  ▼
确认审查立场：甲方 / 乙方 / 中立
  │
  ▼
完整读取合同
  │
  ▼
合同审查 Skill
  │
  ▼
输出风险等级、修改建议、替换条款和需确认问题
  │
  ▼
如用户要求 Word 修订模式：生成 redline-plan.json
  │
  ▼
执行真实 DOCX 修订/批注并完成红线 QA
```

#### 正式文书交付

```text
业务 Skill 生成正文、语义 HTML 或要素式填充数据
  │
  ▼
法律文书出稿前审查
  │
  ├─ PASS / FIXED_PASS：进入导出
  └─ NEEDS_*：退回业务修订、用户确认或补充材料
  │
  ▼
法律文书模板与导出
  │
  ├─ 普通线性文书：draft_checked.html -> html_to_docx.py
  └─ 要素式起诉状：complaint-data.json + fill-plan.json -> fill_docx_template.py
  │
  ▼
DOCX 文件、质控报告与结构体检结果
```

## 快速开始

#### 方式一：通过 Skills CLI 安装

```bash
npx skills add https://github.com/<YOUR_GITHUB>/<YOUR_REPO> -l
npx skills add https://github.com/<YOUR_GITHUB>/<YOUR_REPO> --skill china-legal-skills
```

`china-legal-skills` 是本仓库的公开入口 Skill。

它会要求 Agent 先读取：

```text
skills/legal/法律工作总控/SKILL.md
```

由总控完成路由、材料读取、必要澄清和共享质量控制，再进入具体专业 Skill。

#### 方式二：作为普通 skills 目录安装

```bash
git clone https://github.com/<YOUR_GITHUB>/<YOUR_REPO>.git
mkdir -p ~/.codex/skills
rsync -a <YOUR_REPO>/skills/legal/ ~/.codex/skills/legal/
```

安装后可以直接调用：

```text
法律工作总控 帮我判断这个任务应该走哪个法律工作流。
```

```text
合同审查 审核这份合同，按风险等级输出修改建议。
```

```text
法律咨询助手 帮我回复这个客户咨询，保持微信式简短自然。
```

## 安全边界

Legal Skills w/Ludus Agent 默认强调：

* 不把模型记忆包装成文件事实、现行法规或已核验案例；
* 不把用户对法律关系的命名直接视为已经确认的法律定性；
* 不把用户主张或模型推断静默升级为客观事实；
* 不在未读取关键材料、未完成复查或必要法规校验时生成正式法律意见；
* 面对存在实质竞争性解释的复杂事项，不为了完成任务而强行选择唯一结论；
* 正反复核均必须遵守同一事实和来源边界，不得为了“反方观点”虚构事实、案例或法条；
* 不静默写入台账、系统记录、云文档或日历；
* 不把客户材料、案卷、OCR 中间结果、API Key 或商业数据库凭证提交到公开仓库；
* 不替代律师、法务或专业人士对事实、证据、法律适用和最终文本的判断；
* 不承诺诉讼、仲裁、行政处理、交易谈判或监管沟通结果。
